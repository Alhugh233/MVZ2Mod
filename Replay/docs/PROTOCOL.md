# `.mrep` 回放文件协议

> **规范版本 1**（`ReplayProtocol.SpecVersion = 1`）
> 对应的格式版本：`ver = 10`（`ReplayProtocol.FormatVersion`）
> 实现：`Replay/` 下的 `ReplayProtocol.cs` / `ReplayEnvironment.cs` / `ReplaySamplers.cs` /
> `ReplayPolicy.cs` / `ReplayFile.cs` / `ReplayRecorder.cs` / `ReplayPlayer.cs`
>
> 本文是**规范**（normative）：说「必须」「不得」的地方是实现与第三方工具都要遵守的约束。
> 想了解「为什么这么设计」请看同目录 [DESIGN.md](./DESIGN.md)；
> 想了解「怎么用」请看 [README.md](./README.md)。

---

## 0. 一句话概括

`.mrep` 是**一局关卡的分支状态记录**：一份**关卡起始状态**（关键帧）+ 一串
**玩家语义动作** + 一串**周期性状态指纹**（用来证明「回放真的复现了实战」），
外加一份**环境清单**（游戏版本 + 已装 mod）用于解释「为什么这次没复现」。

编码为 **gzip 压缩的 UTF-8 逐行 JSON**：每行一个**扁平** JSON 对象，第一行固定是 header。

---

## 1. 容器与编码

| 项 | 规定 |
| --- | --- |
| 主文件 | `*.mrep` = gzip（`GZipStream`）压缩的 UTF-8 文本，**不含 BOM** |
| 明文副本 | `*.mrep.json`（可选）= 与主文件**逐字节同内容**的未压缩文本 |
| 行分隔 | `\n`（LF）。允许行尾有 `\r`（读者必须容忍） |
| 每行 | 一个 JSON **对象**，且必须是**扁平**的（见 §1.1） |
| 行顺序 | header 第 1 行；`env` 行紧随其后；`keyframe` 行在 `env` 之后；其余行的顺序要求见 §2 |

> 读者**必须**优先尝试 `.mrep.json`（纯文本，不受 gzip 影响、可人工检视），找不到再读 `.mrep`。

### 1.1 为什么强制「扁平」

本协议的值只允许 **字符串 / 数字 / `true` / `false` / `null`**，
**不得**出现嵌套对象或数组。

原因：读取侧是一个约 60 行的单遍解析器（`FlatJson`），它同时被
「录制器自检」「自测报告」「外部工具」复用。一旦引入嵌套，就得引入一个真正的 JSON 库，
而 Il2CppInterop 环境下的代理程序集既不可靠也不必要。**需要表达复合内容时用分隔符字符串**
（例如 `<c>ed</c>` 用 `,`、`<c>ei</c>` 用 `;`、`<c>rx</c>` 用 `|`），并在本文里写明分隔符。

后续版本**不得**破坏这一条。

## 2. 记录类型

header 与每个记录都用 `k` 字段标明类型。**全部已定义的类型如下**。

| `k` | 名称 | 数量 | 说明 |
| --- | --- | --- | --- |
| —（第 1 行） | header | 恰好 1 | 文件身份、关卡、时间轴、计数、环境摘要、录制参数 |
| `env` | 环境 | 1 行摘要 + N 行条目 | 游戏 / 引擎 / 平台 / 已装 mod（见 §4） |
| `keyframe` | 起始关键帧 | 恰好 1 | 关卡初始状态的完整序列化（见 §5） |
| `fp` | 状态指纹 | 0..N | 一致性判据（见 §6） |
| `ptr` | 指针轨迹采样 | 0..N | 逐 tick 的指针位置与按键掩码（可选特性 `ptr`，见 §7.1） |
| `dlg` | 选项对话框 | 0..N | 对话框选项列表与玩家的选择（可选特性 `dlg`，见 §7.2） |
| `grid` `entity` `blueprint` `bpkey` `lawn` `tool` `set` `reset` | 动作事件 | 0..N | 玩家的语义动作（见 §8） |

### 2.1 顺序与排序规则

- header **必须**是第 1 行。
- `env` 行**必须**紧跟 header、且在 `keyframe` 之前。
  （理由：读者应当能在**不解析关键帧**的前提下就知道环境 —— 回放库列表要先显示版本警示。）
- `keyframe` **必须**只有一行。
- **动作事件行必须按 `t` 非降序**。播放器用单向游标推进事件队列，乱序会静默漏事件。
- `fp` / `ptr` / `dlg` 行的顺序**没有语义**，但实现应当按 `t` 升序写出（便于人工阅读与流式比对）。

### 2.2 向前兼容（重要）

- 读者**必须忽略**它不认识的 `k` 值，并**允许**记录一条警告。
  （未知 `k` 不得让整个文件读取失败。）
- 读者**必须忽略**它不认识的字段名。
- 读者**必须**把「字段不存在」与「字段为默认值」区分开：
  不存在的字段一律按**旧行为**处理（见各字段的「旧文件」说明）。
- header 里**不得**靠字段顺序推断任何东西 —— 一律按名字取值。
- 未知的**能力标记**（§3 `caps`）必须被忽略。

## 3. header

第 1 行。`magic` 必须是 `mrep`；不是就**不得**继续解析。

### 3.1 身份与版本

| 字段 | 类型 | 必须 | 含义 |
| --- | --- | --- | --- |
| `magic` | string | ✅ | 固定 `"mrep"` |
| `spec` | int | ✅(v10+) | **规范版本**：本文的版本。只作人读信息 |
| `ver` | int | ✅ | **格式版本**：读者**只据此**判定兼容性（§3.5） |
| `mod` | string | ✅ | 写文件的 mod 版本 |
| `created` | string | ✅ | 录制开始时刻，ISO-8601（`yyyy-MM-ddTHH:mm:ss`） |
| `end` | string | ✅ | 录制结束原因（`manual-stop` / `quit` / `restart` / `autosave` …） |

### 3.2 环境摘要

明细在 `env` 行（§4）。这里只放**打开文件就要用到**的那几项。

| 字段 | 类型 | 必须 | 含义 |
| --- | --- | --- | --- |
| `game` | string | ✅ | 游戏版本（`Application.version`，标题界面显示的那个） |
| `unity` | string | v10+ | 引擎版本（`Application.unityVersion`） |
| `plat` | string | v10+ | 平台位数（`x86` / `x64`） |
| `tps` | int | ✅ | 逻辑 tick/秒。**协议固定 30**，独立成字段是为了跨客户端换算 |
| `envHash` | string | v10+ | 环境哈希（16 位小写十六进制，算法见 §4.3） |
| `envCount` | int | v10+ | `env` 行里的**条目**数（不含摘要行） |

### 3.3 关卡与时间轴

| 字段 | 类型 | 必须 | 含义 |
| --- | --- | --- | --- |
| `stage` | string | ✅ | 关卡 ID，形如 `mvz2:halloween_2` |
| `area` | string | ✅ | 面积（场景）ID，形如 `mvz2:halloween` |
| `difficulty` | string | ✅ | 难度 ID |
| `seed` | int | ✅ | 关卡随机种子 |
| `startTick` | int | ✅ | 关键帧所在 tick，也是回放的第一个 tick |
| `lastTick` | int | ✅ | 最后一个被记录到的 tick |
| `sw` `sh` | number | v7+ | 录制时的窗口尺寸（像素）。缺失/0 = 无法换算屏幕坐标（恒等换算） |
| `mn` | int | v9+ | 录制开始时的**全局金币**。缺失 = 未知（见 §9.2） |

> `sw`/`sh` 的必要性：事件里的 `sx`/`sy` 是屏幕像素，而「像素 → 世界坐标」的换算含屏幕高，
> 所以换个窗口尺寸再播，同一个像素就指向**别的格子**了。播放时以此把坐标换算回同一个世界点。

### 3.4 内容与计数

| 字段 | 类型 | 必须 | 含义 |
| --- | --- | --- | --- |
| `hasKeyframe` | bool | ✅ | 关键帧是否抓取成功 |
| `keyframeError` | string | 可选 | `hasKeyframe=false` 时的失败原因 |
| `eventCount` | int | ✅ | 动作事件行数 |
| `fingerprintCount` | int | ✅ | `fp` 行数 |
| `ptrCount` | int | v9+ | `ptr` 行数 |
| `dlgCount` | int | v9+ | `dlg` 行数 |

计数器**必须**与文件里实际的行数一致。不一致时读者应当警告（文件可能被手工编辑过）。

### 3.5 录制参数（协议 v10 起；**播放策略的全部依据**）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `fpt` | int | 录制时**实际使用**的指纹采样间隔（tick）。0 = 没有采指纹 |
| `debug` | bool | 这是**调试模式**文件（§10）：逐 tick 采样 + 字段尽量全 |
| `caps` | string | 本文件用到的可选特性，逗号分隔（§7） |
| `samplers` | string | 录制时启用的采样器名，逗号分隔（§6.2）。缺失 = 旧文件 |

### 3.6 兼容性判定（normative）

| 情况 | 处理 |
| --- | --- |
| `magic != "mrep"` | **必须拒绝**读取 |
| `ver` 缺失 / `<= 0` | **必须拒绝**读取（无法判断结构，猜错会静默播错） |
| `ver > ` 读者支持的版本上限 | **必须拒绝**，并提示「请升级回放 mod」 |
| `0 < ver < ` 读者支持的最低版本 | **可以**拒绝；若读者的最低版本 ≤ 该文件，则按旧行为读取 |
| `ver < 10` | **必须**按旧行为读取：缺的字段按各表里的「旧文件」说明取值，`caps` 可由 `ptrCount`/`dlgCount`/`sw`/`sh` 反推 |
| `stage`/`area` 缺失，或 `keyframe.state` 缺失 | **不可播放**（但文件仍可被列表/工具读取） |
| `game` / `envHash` 与当前环境不同 | **只警告，不得阻止播放**（§4.4） |

> 「版本号更高就拒绝」是刻意的：**缺字段**能降级读取，而**字段含义变了**会静默播错。
> 宁可让用户看到一句「请升级 mod」。

## 4. `env` 记录：游戏环境

**一类两形**，靠有没有 `id` 区分。

### 4.1 摘要行

```json
{"k":"env","t":"summary","game":"0.7.0","unity":"2022.3.62f3","plat":"x86",
 "tps":30,"hash":"a1b2c3d4e5f60718","n":9}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `k` | string | `"env"` |
| `t` | string | 固定 `"summary"` |
| `game` `unity` `plat` | string | 同 header 的 §3.2 |
| `tps` | int | 同 header |
| `hash` | string | 环境哈希 |
| `n` | int | 后面跟着多少个条目行 |

### 4.2 条目行

```json
{"k":"env","kind":"builtin","id":"mvz2","name":"Minecraft VS Zombies 2","ver":"5","dv":5}
{"k":"env","kind":"content","id":"mvz2_lab","name":"Laboratory","ver":"4","dv":4}
{"k":"env","kind":"plugin","id":"qoznos.mvz2.replay","name":"MVZ2 Replay","ver":"0.1.0"}
{"k":"env","kind":"runtime","id":"env:game","name":"游戏版本","ver":"0.7.0"}
{"k":"env","kind":"runtime","id":"env:unity","ver":"2022.3.62f3"}
```

| 字段 | 类型 | 必须 | 含义 |
| --- | --- | --- | --- |
| `kind` | string | ✅ | 见下表 |
| `id` | string | ✅ | 稳定标识（**哈希用**） |
| `ver` | string | ✅ | 版本串（**哈希用**） |
| `name` | string | 可选 | 人读名字 |
| `dv` | int | 可选 | 关卡存档数据版本（只有 `builtin`/`content` 有） |
| `note` | string | 可选 | 人读备注 |
| `h` | bool | 可选 | `false` = 这一条**不参与**环境哈希。缺失 = `true` |

`kind` 的取值：

| `kind` | 含义 | `id` | `ver` | 参与哈希 |
| --- | --- | --- | --- | --- |
| `builtin` | 游戏本体 | `mvz2` | 关卡数据版本（`LevelManager.CURRENT_DATA_VERSION`） | ✅ |
| `content` | 游戏内容 mod | 命名空间 | 该 mod 的**关卡数据版本** | ✅ |
| `plugin` | BepInEx 插件 | 插件 GUID | 插件版本 | ✅ |
| `runtime` | 运行环境 | `env:xxx` | 版本串 | ✅（`env:replay` 除外） |

`runtime` 的约定 id：

| id | `ver` |
| --- | --- |
| `env:game` | **游戏版本**（`Application.version`，与 header 的 `game` 同值） |
| `env:unity` | 引擎版本（`Application.unityVersion`） |
| `env:arch` | 进程位数：`x86` / `x64` |
| `env:tps` | 逻辑 tick/秒（`"30"`） |
| `env:replay` | 写文件的 mod 版本（`h:false`，不参与哈希） |

> ⚠️ **不得**用 `mvz2` 这个 id 记录游戏版本：`mvz2` 已经被 `builtin` 占用，
> 而 `builtin` 的 `ver` 按规范是**关卡数据版本**。混用会让「游戏版本」显示成 `5` 这类数据版本号。
> 游戏版本一律用 `env:game`。

> **为什么 `content` 的 `ver` 是关卡数据版本而不是 mod 版本**：
> 关卡关键帧的首行带着「所有内容 mod 的 (命名空间, 关卡数据版本)」，
> 游戏读档时按命名空间逐个比对（`LevelDataIdentifierList.Compare`）。
> 回放要载入的正是同一份数据 —— 所以这个组合**就是「关键帧能不能载入」的判据**。

> **为什么插件也要记**：插件只有 GUID/名称/版本，但任何改过逻辑的插件换了版本，
> 同一份回放就可能不复现。

### 4.3 环境哈希

```
lines = [ (kind|id|ver) for each entry where h != false ]
sort(lines, ordinal)
hash  = FNV-1a-64( 每行 UTF-16 码元逐字符 混合后追加一个 '\n' )
输出  = 16 位小写十六进制
```

顺序无关（先排序）、平台无关（用 UTF-16 码元而不是字节），所以同一套环境在任何机器上得到同一个哈希。

### 4.4 播放时的处理（normative）

1. **必须**重新采集当前环境。
2. **必须**比对，并把差异**完整报告**给用户（`播放小结` 的「录制环境 / ⚠ 环境差异」段）。
3. **不得**因为环境不同而拒绝播放或中断播放。
4. 内容 mod 的**关卡数据版本**差异**必须**单独点名 —— 它属于「必然失败」而不是「略有偏差」，
   混在普通差异里会被用户忽略。
5. 文件没有 `env` 记录（`ver < 10`）时，**必须**退化为只比较 header 的 `game`。

## 5. `keyframe` 记录：关卡起始状态

```json
{"k":"keyframe","tick":1,"state":"<BSON 字符串>"}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `tick` | int | 该状态对应的逻辑 tick，**必须**等于 header 的 `startTick` |
| `state` | string | `SerializableLevelController` 的 BSON 文本（游戏自己的 `SaveGame()` 产物） |
| `error` | string | 抓取失败时的原因；此时 `state` 为 `null` |

### 5.1 约束

- **恰好一行**。多行时读者取第一行并警告。
- `state` 是**游戏自己的序列化格式**（BSON，含所有内容 mod 的标识）。
  协议**不**规定它的内部结构 —— 它属于游戏，随游戏版本变化。
- 因此：**关键帧只能由同一套「游戏 + 内容 mod 组合」载入**。
  跨环境播放时载入失败是预期行为，且**必须**以「环境/数据版本不匹配」的形式报告给用户，
  而不是报成「文件损坏」。
- `state` 是长字符串（几十 KB），会被 JSON 转义（`"` `\` 控制字符）。

> **为什么是「关键帧 + 动作」而不是「种子 + 原始鼠标键盘」**：
> 见 DESIGN.md 第 3 节。要点是：种子无法重建「选卡 / 制品 / 诅咒」的选择，
> 而原始输入无法跨版本；语义动作既小又稳。

## 6. `fp` 记录：状态指纹

**这是「回放是否真的复现了实战」的唯一判据。**

```json
{"t":150,"k":"fp","en":50,"w":0,"fl":0,"cl":false,"ec":6,
 "eh":"48583e6f1b9b37a3","ed":"mvz2:fragment=3,mvz2:gargoyle_statue=3",
 "r":"e31d337f01a3569a","r0":"d4f6390ce984dab3", ...}
```

### 6.1 内置字段

| 键 | 类型 | 含义 | 出现条件 |
| --- | --- | --- | --- |
| `t` | int | 逻辑 tick | 必有 |
| `k` | string | `"fp"` | 必有 |
| `en` | int | 能量（`LevelEngine.Energy` 取整） | 必有 |
| `w` | int | 当前波次 | 必有 |
| `fl` | int | 当前旗数（无尽关的轮数） | 必有 |
| `cl` | bool | 是否已清关 | 必有 |
| `ec` | int | 存活实体数 | 采样器 `state.entities` |
| `eh` | string | **实体集合哈希**（所有实体的 `(id, 定义ID)` 按 id 排序后 FNV-1a） | 同上 |
| `ed` | string | 实体定义直方图 `def=n,def=n`（按定义名排序） | 同上，且 `FullFingerprint` |
| `r` | string | **7 条 RNG 流的合并哈希** | 采样器 `state.rng` |
| `r0`..`r6` | string | 7 条 RNG 流**各自**的哈希 | 同上，且 `FullFingerprint` |
| `rx` | string | 【调试】7 条流的**原始** `x,y,z,w`（hex，流间用 `\|`，分量用 `,`） | 采样器 `dbg.rngRaw` |
| `ei` | string | 【调试】每个实体的明细（`;` 分隔，单条为 `id:定义:血量:x,y,z:分层`） | 采样器 `dbg.entities` |
| `lk` | string | 【调试】关卡序列化里的内部标量（`lt=`levelTime `,eid=`currentEntityID …） | 采样器 `dbg.level` |
| `x_*` | string | 第三方采样器的自定义字段（**必须**用 `x_` 前缀） | 由注册的采样器决定 |

`r0`..`r6` 的顺序**固定**为：

```
0 = level   1 = entity   2 = effect   3 = round   4 = spawn   5 = conveyor   6 = misc
```

> **为什么要 `eh` 与 `ed`**：实体 ID 由关卡内自增计数器分配。
> 只要录制与回放之间有**任何一处生成时机差一两个 tick**，后面的 ID 就整体错位 ——
> 同一个 id 在两边指向不同东西，后果是「动作做到错的东西上」。
> `eh` 告诉你「从哪个 tick 起实体集合就不一样」；`ed` 用可读的方式说出「少了哪一类」。

### 6.2 采样与比对（normative）

- **采样器**（`IReplaySampler`）是唯一的生产者与唯一的口径来源。
  录制与播放**必须**跑**同一批**采样器 —— 否则「一致」就变成了自证清白的废话。
- 采样间隔由**录制侧的配置**决定（`fpt`）；播放侧**不重算间隔**，
  只按「文件里有哪些 `fp` 行」逐个核对（见 §11）。
- **比对的规则是通用的**：对每一条 `fp`，凡是在**录制侧**出现、且键名不属于
  `{t, k}` 的字段，都要求回放侧**逐字相等**。
  - 录制侧没有的字段 → **不比对**（那是「这条指纹只记了一部分」，不是「回放算错了」）。
  - 回放侧算不出来的字段 → **既不算一致也不算不一致**，**必须**单独计数并报告
    （否则「指纹 3/3 一致」会被读成「全都验证过了」）。
- 这条规则让「加一种新指纹」＝注册一个采样器：录制、播放、比对的代码都**不需要改**。
- 长字段（`rx` / `ei` / `lk`）不一致时，报告**必须**给出**首个不同处**及其上下文片段，
  而不是把整串贴出来 —— 前者能直接指出「哪个实体的哪个量先变」。

### 6.3 指纹缺失

- `fp` 行数为 0 时，回放**可以**播放，但**必须**在小结里明确说明「本次没有任何一致性校验」。
- 人为暂停期间错过的指纹直接跳过，不计入不一致。

## 7. 可选特性（`caps`）

`caps` 是逗号分隔的能力标记，缺省为空串。

| 标记 | 含义 | 相关记录/字段 |
| --- | --- | --- |
| `ptr` | 有逐 tick 指针轨迹 | `ptr` 行 |
| `dlg` | 有选项对话框记录 | `dlg` 行 |
| `hfl` | 动作事件带手持标记 | `itg` / `evk` |
| `vp` | 有录制时的窗口尺寸 | `sw` / `sh` |
| `dbg` | 它是**调试模式**文件 | §10 |

**约束**：

- 未知标记**必须**被忽略。
- `caps` 只是**声明**。读者**必须**以「实际有没有这类行」为准：
  声明了 `ptr` 却一条 `ptr` 行都没有时，**应当**警告「文件自述与内容不符」。
- 反向也要检查：有 `ptr` 行却没声明 `ptr` 时，**应当**按「有」处理并警告。

### 7.1 `ptr`：逐 tick 指针轨迹

```json
{"k":"ptr","t":37,"sx":-458.5,"sy":221.25,"mb":1}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `t` | int | 逻辑 tick |
| `sx` `sy` | number | **像素**坐标（与事件同制，需配 `sw`/`sh` 换算） |
| `mb` | int | 按键掩码：左=1 右=2 中=4（可叠加） |

**为什么需要**：有一类关卡内容不看指针事件的参数，而是每帧直接问
「鼠标现在在哪 / 哪个键按着」—— 打砖块挡板、重装兵器（按住才开火）、矿车（目标点）、
碾压墙（每次按下扣进度）。没有轨迹它们根本重现不了。

**按需录制**：只有「本关确实存在会读实时指针的内容」时才写。
判定由 `ReplayCompat.RegisterPointerConsumer` 注册（原版内置 4 个，第三方可注册自己的）。
判定一旦成立，本关剩下时间**一直**录（不因那个实体中途消失而停，否则会留下空洞）。

**播放**：存在轨迹时，掩盖码与位置**一律以轨迹为准**；轨迹未覆盖的 tick
退化为「由事件推导」的按键状态。

### 7.2 `dlg`：选项对话框

```json
{"k":"dlg","t":420,"title":"…","desc":"…","op":"付钱|离开","sel":0,"selName":"付钱"}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `t` | int | 弹出时刻的 tick |
| `title` `desc` | string | 标题与正文（人读 + 排障） |
| `op` | string | 选项文本列表，`\|` 分隔 |
| `sel` | int | 玩家选了第几项（`-1` = 录制结束时也没选） |
| `selName` | string | 所选那一项的**文本** |

**为什么除了下标还要记文本**：上锁的箱子的选项是**按当前金币动态生成**的
（钱够才有「付钱」那一项）。金币来自全局存档、不在关卡关键帧里，
所以「录的时候有钱、放的时候没钱」会让**选项个数都不一样** —— 只靠下标会选错甚至越界。
播放时**必须**优先按文本定位，文本找不到时**不得**猜测。

## 8. 动作事件

每条动作事件都有一个 `t`（tick）与一个 `k`（种类）。**动作事件行必须按 `t` 非降序。**

所有事件共有的可选字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `pid` | int | 指针 id（多指设备） |
| `btn` | int | 按键：左=0 右=1 中=2 |
| `ia` | int | 交互类型：Hover=0 Enter=1 Stay=2 Exit=3 Hold=4 Streak=5（噪音交互**不记录**） |
| `sx` `sy` | number | 指针**屏幕**像素坐标（v2+） |
| `wx` `wy` `wz` | number | 射线命中的**世界**坐标（v2+） |
| `itg` `evk` | bool | 该事件之后手持蓝图上的「立即触发 / 立即激发」标记（v8+，**两个必须同时存在**才算有效） |

### 8.1 各 `k` 的专属字段

| `k` | 含义 | 专属字段 |
| --- | --- | --- |
| `grid` | 点在某格上 | `lane` `col` |
| `entity` | 点在某个实体上 | `id`（实体 ID）、`def`（定义 ID，v3+）、`ex` `ey` `ez`（记时坐标，v3+）、`lyr`（格子分层，v6+） |
| `blueprint` | 点了某张卡 | `idx`、`cv`（是否传送带） |
| `bpkey` | 卡片热键 | `idx`、`cv`、`key`（`KeyCode` 的整数值） |
| `lawn` | 点在草坪上 | `area` |
| `tool` | 点了工具按钮 | `name`（`pickaxe` / `starshard` / `trigger`） |
| `set` / `reset` | **v1 遗留**：工具点击记成派生的手持物变化 | `type` |

### 8.2 实体事件的锚点（关键）

实体 ID 会因任何一处生成时机不同而**整体错位**。因此 `entity` 事件**必须**记录
`def`（定义 ID）与 `ex`/`ey`/`ez`（记时坐标），v6+ 还应记录 `lyr`（格子分层）。

播放时按**三级**解析目标：**ID → 同定义 + 最近坐标 → 放弃**。

- 匹配半径取**半格**（一个格子 = `AreaMeta.GridWidth`，默认 80 草坪单位）。
- 同一格最多同时站 4 个可被镐子挖掉的器械（承载位 / 保护位 / 主要位 / 工具位），
  它们**坐标完全相同** —— 所以 `lyr` 是必需的：只按坐标最近会在这一格上选错对象。
- 三级都失败时**必须跳过该事件**并以「目标找不到」计数，**不得**随机挑一个实体。

## 9. 全局状态（不在关键帧里的那些）

### 9.1 起始金币（`mn`）

金币属于**全局存档**，不在关卡关键帧里，但它参与关卡逻辑的**分支**
（上锁的箱子按「钱够不够」决定要不要生成「付钱」那一项）。
录制时把开录那一刻的金币写进 header 的 `mn`；播放时用它给「金币影子」播种。

`mn` 缺失（旧文件）时**必须**退回「按真存档播种」的旧行为。

### 9.2 回放期间不得改动存档（实现约束）

回放**必须**保证：挣/花的钱只进影子、统计与解锁一律不写盘。
这是实现约束而不是格式约定，但**违反它会让用户"只是看了个回放"就丢掉进度**，
所以在这里显式写出。

> ⚠️ 已知实现陷阱（0.7.0 实测）：存档护栏**在「进入关卡场景」期间不得处于启用状态**，
> 否则进程直接 `0xC0000005` 崩溃。护栏的启用必须推迟到「关卡已就绪、开始按 tick 播放」那一刻。
> 详细证据链见 DESIGN.md §4.4.15。

## 10. 调试模式（**研发专用，默认关闭**）

调试模式的存在意义只有一个：**把「回放从第几个 tick 起与实战不符、是谁先变」定位出来。**
它**不是**给玩家用的功能。

### 10.1 开启方式

配置文件的 `[Debug]` 段（**只有录制侧读它**）：

| 配置项 | 默认 | 含义 |
| --- | --- | --- |
| `Enabled` | `false` | 总开关 |
| `EveryTick` | `true` | 逐 tick 采指纹（而不是每 `FingerprintInterval` 个 tick） |
| `RawRng` | `true` | 写原始 RNG 状态（`rx`） |
| `EntityDetail` | `true` | 写每个实体的明细（`ei`） |
| `LevelScalars` | `true` | 写关卡内部标量（`lk`） |
| `EntityLimit` | `0` | 实体明细条数上限（0 = 不限） |

### 10.2 文件表现

| 位置 | 表现 |
| --- | --- |
| header | `debug=true`、`fpt=1`、`caps` 含 `dbg`、`samplers` 含全部调试采样器 |
| `fp` 行 | **每个 tick 一条**，且带 `rx` / `ei` / `lk` |
| 体积 | 比常规模式大 1-2 个数量级（典型：单局几十 MB） |

### 10.3 播放时的处理（normative）

- 播放**必须**只看文件：`debug=true` ⇒ 启用调试采样器去核对那些字段，
  **不得**去读本机的 `[Debug]` 配置。
- `debug=false` 的文件**不得**因为本机开着调试模式而改变行为。
- 因此：**调试文件可以交给别人播**，即使对方没开调试模式，也能得到完整的差异报告。

### 10.4 为什么值得单独做一个模式

普通模式为了文件大小，只能牺牲「定位精度」：
每 150 tick 一条指纹、只说「不一致了」。
调试模式下每 tick 一条、且带原始 RNG 与逐实体明细，
于是「第 37 tick、spawn 流的第 3 次 Next 之后跑偏、差的是那个 zombie 的血量」
这类结论才拿得到。两种模式服务完全不同的场景，合在一起只会两头不讨好。

## 11. 录制行为 vs 播放行为（**协议的核心分工**）

> **录制行为取决于配置文件；播放行为取决于回放文件。**

这是规范里最重要的两条约束，实现**不得**违反。

### 11.1 录制

| 事项 | 来源 |
| --- | --- |
| 采样间隔、是否完整指纹、是否录指针轨迹、是否记对话框 | `[General]` 配置 |
| 调试字段与逐 tick 采样 | `[Debug]` 配置 |
| 输出目录、明文副本、条数上限 | `[General]` 配置 |

- 配置**必须**在「开始录制」那一刻**快照一次**，整场不再重读。
  （否则玩家中途改配置会让**同一个文件内部**自相矛盾。）
- 快照里「实际生效」的部分**必须**写进 header（`fpt` / `debug` / `caps` / `samplers`）——
  文件要能自己说明「我是按什么参数录的」。

### 11.2 播放

| 事项 | 来源 |
| --- | --- |
| 核对哪些 tick、哪些字段 | **文件**（`fp` 行 + `samplers` + `debug`） |
| 用不用指针轨迹、答不答对话框 | **文件**（有没有 `ptr` / `dlg` 行） |
| 屏幕坐标怎么换算 | **文件**（`sw` / `sh`） |
| 用不用手持标记 | **文件**（`hfl`） |
| 环境差异算不算问题 | **文件**（`env`） + 当前环境 |

- 播放**不得**为了「语义行为」读取任何配置项。
  （配置只影响**表现**：假鼠标、对话框停留秒数、探针。）
- 净效果：**同一个文件在任何机器、任何配置下播放，行为完全一致。**

### 11.3 为什么两者不共用状态源也可以

录制器关心的是「玩家做了什么」（事件流），播放器关心的是「该按什么顺序做什么」
（按 tick 派发的队列）。两者的数据结构天然不同，硬合成一个只会互相拖累。

**但两者必须共用**：

1. **指纹采样的算法**（同一批采样器）—— 否则「一致」无意义。
2. **事件字段的语义**（本文）—— 否则写出来的东西自己读不回来。
3. **环境的定义**（§4）—— 否则比对无从谈起。

### 11.4 可替换的行为接口

协议**鼓励**（但不要求）实现把下列概念做成可替换的接口，以便第三方扩展：

| 概念 | 接口 | 注册 | 作用 |
| --- | --- | --- | --- |
| 一种状态指纹 | `IReplaySampler` | `ReplaySamplers.Register` | 加新指纹字段；录制/播放/比对自动生效 |
| 环境条目 | `IReplayEnvSource` | `ReplayEnvSources.Register` | 把自家版本/数据写进回放 |
| 会读实时指针的内容 | — | `ReplayCompat.RegisterPointerConsumer` | 让指针轨迹按需开始录制 |
| 录制策略 | `ReplayRecordOptions` | `FromConfig()` | 配置 → 行为（快照） |
| 播放策略 | `ReplayPlaybackPolicy` | 从 `ReplayFile` 推导 | 文件 → 行为 |

**第三方采样器的硬性要求**：

- 字段名**必须**以 `x_` 开头（协议保留 2 字符短键给内置字段）。
- 采样器名**必须**唯一（重复注册会被忽略）。
- 采样器**不得**修改关卡状态 —— 它只读。

## 13. 版本历史

| `ver` | 新增 |
| --- | --- |
| 1 | 早期草案：无指针位置；工具点击记成派生的 `set`/`reset` |
| 2 | 事件带指针位置（`sx`/`sy`/`wx`/`wy`/`wz`）；工具点击记成 `tool` |
| 3 | `entity` 事件带 `def` 与 `ex`/`ey`/`ez` |
| 6 | `entity` 事件带 `lyr`（格子分层） |
| 7 | header 带 `sw`/`sh` |
| 8 | `blueprint`/`bpkey`/`entity` 事件带 `itg`/`evk` |
| 9 | 新增 `ptr` 与 `dlg` 两种记录；header 带 `mn` |
| **10** | **规范化协议**：header 带 `spec`/`unity`/`plat`/`envHash`/`envCount`/`fpt`/`debug`/`caps`/`samplers`；新增 `env` 记录；`fp` 允许任意附加字段（调试字段 `rx`/`ei`/`lk`、第三方 `x_*`）；明文规定录制/播放的策略分离与可替换接口 |

> 版本号**只增不改**：字段只加不删含义，行结构只加不删类型。
> 需要改变已有字段的含义时，**必须**升 `ver` 并在本表登记。
